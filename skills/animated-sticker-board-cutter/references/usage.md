# 使用说明

## 完整流程概览

本 Skill 已固化四个阶段：

1. 根据参考角色制作身份一致的 4×2、8 格静态角色图。
2. 根据 8 格图生成严格约束的 Gemini 10 秒动画提示词。
3. 用户把 Gemini 返回的 MP4 交回 Codex；也可以从已有视频直接开始。
4. 本地切割、连通去白底、导出 APNG/GIF、检查并打包 ZIP。

如果已经有中间产物，直接从对应阶段开始，不必重做前面的步骤。

## 适用范围

本 Skill 面向身份一致的角色动态表情包。标准输入可以是角色参考图、4×2 静态图板，或已经生成好的动画图板视频。切割阶段要求角色在固定格子中运动、镜头固定、背景为白色或近白色；默认处理 4×2、8 格图板，也支持其他行列数。

它不适合复杂背景、移动镜头、跨格角色或频繁切镜的视频。

## 从角色参考图开始

在 Codex 中说：

```text
使用 $animated-sticker-board-cutter，基于我上传的角色图制作一套 4×2、8 格动态表情包。
保持角色身份、关键特征和服装一致。先生成静态图板和 Gemini 10 秒视频提示词；我返回视频后，再本地切割成透明 APNG 与 GIF。
```

静态图板要求：

- 横向 4×2 排列，8 个角色按从左到右、从上到下阅读。
- 角色身份、脸型或设备形状、关键配件、服装风格保持一致。
- 8 种不同的强烈表情和姿势。
- 角色之间保留透明间距，不跨格、不重叠。
- 不要文字、编号、水印、背景和阴影；最好不要格线。

## Gemini 10 秒视频提示词模板

将接受后的 4×2 图板上传到 Gemini，并使用下面的结构。把动作对替换为当前角色适合的内容：

```text
使用我上传的 4×2、8 格角色图作为唯一的角色身份、造型、服装和构图参考，生成一段约 10 秒、16:9 的动画视频。

画面要求：
- 纯白色背景
- 不要格线、编号、字幕、文字和水印
- 8 个角色的位置和大小保持固定
- 每个角色始终留在原来的格子范围内，不能跨格或重叠
- 镜头固定，不切镜、不缩放、不平移、不重新构图
- 不增加新角色，不改变角色身份、头部造型、关键特征和服装

动画节奏：
- 前 5 秒和后 5 秒必须呈现完全不同的动作、表情和情境
- 约在第 5 秒自然切换
- 动作幅度明显，表情夸张，适合聊天 Meme reaction
- 不要只做眨眼、呼吸、轻微摇摆等细小变化

8 格动作，按从左到右、从上到下排列：
1. 【前半动作】→【后半动作】
2. 【前半动作】→【后半动作】
3. 【前半动作】→【后半动作】
4. 【前半动作】→【后半动作】
5. 【前半动作】→【后半动作】
6. 【前半动作】→【后半动作】
7. 【前半动作】→【后半动作】
8. 【前半动作】→【后半动作】

整体保持轻微低保真互联网 Meme 质感，但角色轮廓清晰。不要场景背景、镜头特效、粒子遮挡或元素跨格。
```

收到视频后先检查：4×2 位置是否固定、角色有没有跨格、镜头有没有移动、背景是否接近白色。合格后再进入切割。

## 从已有视频直接开始

在 Codex 中直接说：

```text
使用 $animated-sticker-board-cutter，把这个 4×2 视频图板切成 8 个透明动态表情。
使用前 2 秒，名称依次为：爆笑、震惊、疑惑、委屈、得意、翻白眼、无语、愤怒。
```

只要同时提供视频文件，Codex 就会跳过静态图板和提示词阶段，直接检查视频、运行本地切割、验证透明度，并给出下载链接。

## 命令行用法

```bash
python3 ~/.codex/skills/animated-sticker-board-cutter/scripts/export_sticker_board.py \
  "/绝对路径/输入视频.mp4" \
  --output "/绝对路径/新的输出目录" \
  --columns 4 \
  --rows 2 \
  --start 0 \
  --duration 2 \
  --labels "爆笑,震惊,疑惑,委屈,得意,翻白眼,无语,愤怒"
```

输出目录必须是新目录或空目录，脚本不会清空已有文件。

## 选择不同动作时段

Gemini 的 10 秒视频通常在约第 5 秒切换动作：

- 导出前半段动作：`--start 0 --duration 2`
- 导出后半段动作：`--start 5 --duration 2`
- 从第 6 秒开始：`--start 6 --duration 2`

建议每个动态表情保留约 2 秒，动作应在该片段内完整、明显并可循环。

如果需要把前后两套动作都做成表情包：

1. 用 `--start 0 --duration 2` 输出前半段 8 个表情。
2. 换一个新目录，用 `--start 5 --duration 2` 输出后半段 8 个表情。
3. 为两次输出提供不同名称，最终得到 16 个动态表情。

## 格子识别模式

`--grid-mode auto` 是默认模式：

1. 尝试识别贯穿图板的黑色或深色格线。
2. 找到正确数量且间距规律的格线时，沿格线内侧裁切。
3. 没有格线时，自动按画面宽高等分。

可以手动指定：

```bash
--grid-mode equal
```

适合完全无格线、每格严格等宽等高的视频。

如果自动识别失败但已经知道格线中心坐标，可指定：

```bash
--grid-mode lines \
--vertical-lines "50,344,639,935,1228" \
--horizontal-lines "68,360,653"
```

4 列需要 5 条竖线，2 行需要 3 条横线。

## 透明背景参数

默认参数：

```bash
--white-threshold 235
```

其含义是先在遮罩副本中把近白色像素标准化，再仅清除与格子边缘连通的白色区域。原始角色颜色不会被标准化。

- 仍有白底或白色碎边：尝试 `230` 或 `225`。
- 角色浅色外壳、白色边缘被削掉：尝试 `240` 或 `245`。
- 背景不是白色或近白色：不要继续降低阈值，应换用视频抠像或 AI 分割方法。

不要改成全局白色键控；全局键控会把眼睛、衬衫和浅色外壳挖空。

## 输出规格

默认产生：

```text
输出目录/
├── APNG_透明高清/
│   ├── 01-爆笑.png
│   └── ...
├── GIF_聊天兼容/
│   ├── 01-爆笑.gif
│   └── ...
├── 预览_4x2_透明表情.png
├── 导出报告.json
├── 动态表情_APNG透明高清.zip
├── 动态表情_GIF聊天兼容.zip
└── 动态表情_全部格式.zip
```

- APNG：默认 320×320、24 fps、透明背景、无限循环。
- GIF：默认 240×240、12 fps、透明背景、无限循环，便于聊天软件导入。
- 预览图：按照原网格顺序排列，只用于检查，不是需要再次切割的成品。
- 导出报告：记录输入、识别到的格线、各格裁切坐标、帧数、时长、透明角检查和唯一帧数。

## 调整尺寸和帧率

```bash
--apng-size 320
--gif-size 240
--apng-fps 24
--gif-fps 12
```

更高的尺寸和帧率会显著增加 APNG 文件体积。聊天使用通常无需提高。

## 测试单格

修改参数前可先快速测试第一格：

```bash
--limit 1 --duration 0.5
```

测试必须写入新的空目录。确认透明边缘和裁切无误后，再导出完整 8 格。

## 依赖与故障排查

需要：

- `ffmpeg`
- `ffprobe`
- Python 3
- Pillow（Python 的 `PIL` 模块）

常见问题：

- “没有检测到格线”：无格线视频可直接使用 `--grid-mode equal`。
- “检测到的格线数量不对”：降低 `--line-threshold`，或提供明确的格线坐标。
- 某一帧突然出现完整白底：提高视频生成稳定性；脚本已使用多边缘取样，但角落持续变色会影响连通去背。
- 角色被裁断：检查角色是否跨格；无格线视频确认使用 `equal` 模式。
- 输出目录非空：使用新的目录名，不要删除不确定来源的旧文件。

## 完成标准

只有当报告中所有文件均通过以下检查，才算完成：

- 动画帧数大于 1，且存在多个不同帧。
- 总时长与目标时长接近。
- 四个画布角均透明。
- 预览中没有整块白底、格线、相邻角色或明显裁断。
- 三个 ZIP 均能正常打开。
